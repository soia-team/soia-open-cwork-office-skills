# soia-media-compose-article-draft

媒体内容工作流的**成文环节（写）**：把 `distill` 产出的观点，写成一篇可发布的文章草稿。

## 客户可读说明

### 这个技能可以做什么

把 distill 提炼出的观点写成成文草稿。以用户观点为骨、vault 摘抄为料，生成可继续交给 publish 的文章。可指定公众号/知乎/随笔风格

| 客户想要 | 技能会做 | 客户能看到 |
|---|---|---|
| 完成本技能覆盖的工作 | 读取用户请求、必要上下文和本技能正文流程，执行最小可靠步骤 | 客户会看到 Obsidian/vault 文件变更、终端日志、生成产物路径和最终回执。 |
| 缺少依赖、权限、配置或 key | 停止需要外部状态的动作，明确指出缺什么 | 安装命令、申请地址、配置路径或需要客户确认的问题 |
| 执行完成 | 汇总成功、跳过、失败、文件变更和验证结果 | 一段可复制进工单/日志的完成回执 |

### 客户如何使用

1. 用自然语言说明目标，并提供必要输入：文件、URL、repo、workspace、proposal、vault 或平台账号状态。
2. 能 dry-run 或预览的动作先给预览；涉及删除、覆盖、发送、发布、写远端状态时先征求客户确认。

## 核心原则

- **观点是你的，文章是你的**。compose 以你 distill 出的观点为骨架，用 vault 里的摘抄 / 文章作论据，组织成通顺文章。**不凭空造观点、不加你没表达过的判断**。
- 缺料就问，不编。

## 流程

1. **收集素材**：
   - 单篇 → 某文章的 `## 我的看法` + `## 原文` 摘要
   - 主题 → distill 模式 B 产出的 `50_草稿/…观点综述.md`，或某 MOC 下多篇的「我的看法」
2. **沿用角度与风格**：先用本次已给定的角度、大纲、标题和平台要求；缺少定位时按需读 vault 的个人说明书。只有关键差异会改变结果时询问，不重复确认已给定内容。
3. **搭结构**：开头（钩子/问题）→ 主体（你的观点 + 论据）→ 结尾（升华/行动）；跨平台稿件的「序」写在文档头部元数据（frontmatter）中，**不插进公众号正文首段**，正文保持自然起笔。用户要求先审大纲时等待确认；否则沿已给定或合理推导的大纲直接成文，并允许后续修改。
4. **成文**：按大纲写，你的观点为主线，摘抄 / 文章为佐证（用 `[[]]` 双链注明来源）。
5. **落草稿**：`<vault-drafts-dir>/YYYY-MM-DD-<标题>.md`，frontmatter `tags:[草稿]`、`status:草稿`、`source_notes:[[…]]`（来源笔记）。
6. **回执**：告知草稿路径、字数、结构，提示"要改哪段告诉我；满意后按目标平台选择 `publish-*` 家族"。

## 标题与摘要工序

沿用用户已给定的标题；未指定或用户要求选择时提供候选。根据账号定位区分**流量钩子体**（知乎/大众科普）与**极简意象体**（自省随笔/家庭号，少说教、淡化“我”字、书生气），**不同体裁不要混用钩子套路**。

| 模式 | 适用场景 | 命名公式 / 要求 |
|---|---|---|
| 流量钩子体 | 大众传播、知识科普、痛点攻略 | 数字盘点 / 反常识 / 提问 / 对比冲突 / 结果承诺 / 场景代入 / 权威背书 / 悬念留白（如「为什么你读了很多书却记不住？」） |
| 极简意象体 | 自省随笔、人物/成长札记、克制长文 | 八字对仗式（`《行至半山，止息内耗》`）/ 四至六字词牌式（`《半山观心》`、`《顺其自然》`）/ 合集编号式（`《半山观心 · 01｜行至半山，止息内耗》`） |

**推荐语 / 摘要（`digest`）与文档头部「序」分工**：交付草稿时在文档头部 frontmatter 区分三层元数据——`series_intro:` 放合集或系列总推荐语；`preface:` 放本篇长序（供小红书导语、系列引荐等平台复用）；`digest:` 放本篇公众号单篇推荐语（建议控制在 **20–40 字**，紧扣本篇自身内容、定调留白，不用系列总推荐语直接顶替）。这三项均属于头部元数据/平台推荐语，**不进入公众号正文**。

## 发表前勘误清单与去 AI 味自检

1. **原稿勘误清单（只检不擅改，用户口述/手写底稿必过）**：交稿或送入 `publish` 前先核查六类硬伤——重字（如「决定决定」）、用词规范（「其它」→「其他」）、`的/地/得` 混用、缺顿号或引用符号、漏字/多字、同音错别字。先以 **「位置 / 原文 / 建议修改 / 原因」** 清单呈报确认，**绝不顺手替用户重写个人语调或修改原观点**；确认后再落地编辑。
2. **去 AI 味自检**：按高频问题轻改——套路开场（在这个时代、随着…发展）、空洞大词（卓越、颠覆性）、假金句（听着猛但没信息增量）、破折号滥用、bullet 堆叠（能写成自然段却硬拆成列表）、单句顺滑但段落间无信息推进。

多数情况做**轻改**：只处理清单命中的具体问题，不重写全文。若原稿明显不像成稿（像资料整理稿、提纲稿、AI 草稿初版），升级到**深改**并向用户说明原因；深改产出写入新文件，不覆盖初稿。

## 边界

- 只落 `50_草稿/`，不碰摘抄原文。
- 观点必须来自用户（distill 产出或直接口述），AI 不虚构立场。
- 引用 vault 内容用双链 `[[]]` 注明。

## 闭环位置

```
clip(收) → organize(整理) → distill(点) → ★compose(写) → publish(发)
```

上游 `distill` 给观点；下游 `publish` 把成文适配多平台发布。
